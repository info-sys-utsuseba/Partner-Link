# Partner-Link チャットボットシステム テスト仕様書

## 1. 概要
本ドキュメントは、Partner-Link チャットボットシステム（Web版）の品質を担保するためのテスト仕様書です。
フロントエンドのUI/UX、バックエンドのAPI通信、AIによる回答生成ロジック、およびデータベース（Supabase）へのログ保存機能について、正常系・異常系・バウンダリー（境界値）テストの項目を網羅的に定義します。

## 2. テスト環境・前提条件
- **対象ブラウザ**: Chrome, Safari, Edge, Firefox（各最新版）
- **対象デバイス**: PC（デスクトップ）, スマートフォン（iOS/Android）
- **必須環境変数**: 
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `OPENAI_API_KEY` (本番・ステージング環境)

## 3. テスト項目一覧

### 3.1. フロントエンド（UI/UX）テスト

#### 正常系テスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| UI-N-01 | 初期画面表示 | トップページにアクセスする | ヘッダー、ウェルカムメッセージ、入力フォームが正しく表示されること |
| UI-N-02 | メッセージ送信（Enter） | テキストを入力し、Enterキーを押下 | メッセージが送信され、入力欄が空になること |
| UI-N-03 | メッセージ送信（ボタン） | テキストを入力し、送信ボタンをクリック | メッセージが送信され、入力欄が空になること |

| UI-N-05 | 処理中インジケーター | メッセージ送信直後 | 「回答を生成中...」のインジケーターと送信ボタンの非活性化が確認できること |
| UI-N-06 | 自動スクロール | チャット履歴が画面高さを超えるまで送信 | 新しいメッセージが追加されるたびに、最新のメッセージ位置まで自動スクロールされること |
| UI-N-07 | セッションIDの永続化 | ページをリロードする | `sessionStorage` に同一の `partner-link.sessionId` が保持されていること |

#### 異常系・バウンダリーテスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |

| UI-E-01 | 空文字送信 | 入力欄が空、またはスペースのみの状態で送信操作 | 送信ボタンが非活性であり、Enterを押しても送信処理が走らないこと |

### 3.2. バックエンド（API & AIロジック）テスト

#### 正常系テスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| API-N-01 | ナレッジベース合致（高信頼度） | ナレッジベースに存在する質問（例：「助成金の正式名称は？」）を送信 | ナレッジベースの回答がそのまま返却されること |
| API-N-02 | LLM回答生成（中〜低信頼度） | ナレッジに関連するが表現が異なる質問を送信 | ナレッジベースをコンテキストとして参照し、LLMが適切な回答を生成すること |
| API-N-03 | エスカレーション提案（ナレッジ外） | ナレッジに全く関係ない質問（例：「おすすめのピザ屋は？」）を送信 | 「事業パートナー公式LINE」へのエスカレーションを促す回答が返却されること |
| API-N-04 | 禁止用語の置換（サニタイズ） | 回答生成プロセスで「ミニマム」「最小」「最低」が含まれるケースをシミュレート | 出力前に「スタンダード」「スタートアップ」等に置換され、禁止用語が露出しないこと |

#### 異常系・バウンダリーテスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| API-E-01 | パラメータ不足 | `query` を空文字、またはキー自体を含めずにPOSTリクエスト | HTTP 400 Bad Request と共に `{ error: "query is required" }` が返却されること |
| API-E-02 | OpenAI APIキー未設定 | `.env` から `OPENAI_API_KEY` を削除して質問を送信 | エラーでクラッシュせず、フォールバックの仮応答（または適切なエラーメッセージ）が返却されること |
| API-E-03 | OpenAI API障害 | OpenAI APIのレートリミット到達やサーバーダウンをシミュレート | 500エラーまたはタイムアウトとなり、フロントエンドにエラーレスポンスが返ること |

### 3.3. データベース（Supabase ログ保存）テスト

#### 正常系テスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| DB-N-01 | ログの正常保存 | チャット画面から質問を送信し、回答を得る | `raw_interaction_logs` テーブルに `session_id`, `query`, `answer`, `created_at` が正しく記録されること |
| DB-N-02 | セッションIDの紐付け | 同一ブラウザタブで複数回質問を送信 | DB上で同一の `session_id` を持つ複数のログレコードが作成されること |

#### 異常系テスト
| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| DB-E-01 | DB接続エラー時の挙動 | SupabaseのURLやキーを無効なものに変更して質問送信 | DB保存には失敗するが、ユーザーへの回答返却（APIレスポンス）はブロックされずに完了すること（※現在の実装仕様に依存。要確認） |
| DB-E-02 | セッションIDなしのリクエスト | `sessionId` を含めずに直接APIへPOSTリクエスト | `session_id` が `null` の状態で、エラーにならずログが保存されること |
| DB-E-03 | 匿名クライアントの権限確認 | ブラウザ等の匿名クライアントから直接 `raw_interaction_logs` を `SELECT` しようとする | RLS（Row Level Security）により、読み取りが拒否（空結果またはエラー）されること |

### 3.4. セキュリティテスト

| 項番 | テストケース | 操作・入力 | 期待される結果 |
|:---|:---|:---|:---|
| SEC-01 | XSS（クロスサイトスクリプティング） | `<script>alert('xss')</script>` を質問として入力・送信 | スクリプトが実行されず、テキストとして表示されること |
| SEC-02 | SQLインジェクション | `'; DROP TABLE raw_interaction_logs; --` を質問として入力・送信 | SupabaseのORMが適切にエスケープし、DBへの不正操作が行われないこと |
| SEC-03 | 環境変数の露出確認 | ブラウザの開発者ツール（ネットワーク・ソース）を確認 | `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY` 等のサーバーサイド環境変数がクライアントに露出していないこと |
| SEC-04 | APIへの直接アクセス | ブラウザ外から `POST /api/chat` に任意のJSONを送信 | 不正なリクエスト（`query` 空文字など）には400エラーが返却されること |
| SEC-05 | 個人情報の非露出 | 代理店名・担当者名が含まれる質問を送信 | 回答内に他の代理店の個人情報が含まれないこと（ナレッジベースの匿名化確認） |

## 4. テスト実施手順

### 4.1. ローカル環境でのテスト実施

```bash
# 1. 依存パッケージのインストール
npm install

# 2. 環境変数の設定
cp .env.example .env.local
# .env.local に各種APIキーを設定

# 3. 開発サーバーの起動
npm run dev

# 4. ブラウザで http://localhost:3000 にアクセスして手動テスト実施
```

### 4.2. 本番環境（Vercel）でのテスト実施

本番URL: **https://partner-link.vercel.app/**

Vercel ダッシュボード: **https://vercel.com/utsuseba/partner-link**

本番環境では以下の点に注意してテストを実施すること。

- テスト用の質問はナレッジベースに記載された実際の質問を使用し、個人情報を含む質問は送信しないこと。
- DB ログは Supabase コンソールの `raw_interaction_logs` テーブルで確認できること。
- OpenAI APIのコスト発生に注意し、負荷テスト（NF-04）は本番環境では実施しないこと。
